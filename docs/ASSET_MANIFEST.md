replace it.

Statuses:

| Status | Meaning |
|---|---|
| `placeholder` | Temporary stand-in. **Never presented as final equipment.** |
| `incoming` | The real asset is being prepared. |
| `approved` | The real asset is registered and rendering. |

### Why the supplied chair GLB is not the default rendering

`scripts/inspect-glb.mjs` reports:

```
generator:       https://github.com/mikedh/trimesh
materials:       0
images:          0
attributes:      POSITION          ← no normals, no UVs
vertices:        9626
triangles:       20000
dimensions:      1.961 x 1.548 x 1.234
components:      6                 ← chair body + stool-like body + 4 small parts
```

It is a raw mesh export, not a prepared asset. The loader compensates for
everything that can be compensated for — computing normals, supplying zeroed
UVs, applying a placeholder PBR material, centring the bounding box and
grounding the model on the floor — but the silhouette remains a rough scan.

The registry therefore renders a **deliberately composed procedural scene**
today while keeping the file registered at its final path:

```ts
dentalChair: {
  src: '/models/dental-chair/dental-chair.glb',   // final destination
  renderMode: 'procedural',                        // ← flip to 'gltf' when ready
  status: 'placeholder',
}
```

Set `renderMode: 'gltf'` and `status: 'approved'` when the authored model is
ready. No scene code changes.

## External imagery

The pre-existing catalogue pages (`/services/[slug]`) reference Unsplash
photographs. These are third-party stock images standing in for real
equipment photography. They are **not** presented as photographs of a specific
facility — replace them with real photography before launch, and remove any
that imply a rating or a verified badge the platform cannot substantiate.

## Handoff checklist

For every new model, provide:

- [ ] Source `.blend`
- [ ] Exported `.glb`
- [ ] Real-world dimensions and unit scale
- [ ] Forward / up axes and origin position
- [ ] Camera framing recommendation (position, target, FOV)
- [ ] Material and texture inventory
- [ ] Polygon and texture budget report
- [ ] Interactive node names, if any
- [ ] Static poster render for the `fallback` path
- [ ] Mobile quality variant, if produced
- [ ] Licence / ownership confirmation

See `ASSET_GUIDE.md` for the full Blender export checklist.
